## Repeat-test contract

`scripts/run-native-soak.py` drives only the dedicated BARO emulator and isolated ADB server. Each of 300 rows represents a real Activity launch, live/cached Open-Meteo weather, actual GLES frame, both-direction page changes, one dial detent, a real canvas gear press, a language button click, settings close and Activity close. Every third row also cancels a page gesture; every fifth backgrounds/resumes; every tenth recreates, plus four Fine/motion-on recreation cases across both languages and orientations. Rendering threads must return to zero after every close. The matrix has 150 Chinese/150 English starts, 150 landscape/150 portrait, 25 starts per purpose, 60 Fine/240 Block and 150 motion-on/150 motion-off. The default runs all 300 cycles in one process so cumulative retention is visible; the collector can also split explicit batches. Separately, production-only force-stop/cold launches are measured by Android `am start -W` and `dumpsys meminfo`.

Logs record every row's source, PID, launch-to-first-art interval, actual provider fetchedAt, cache bytes, post-interaction one-second CPU time, PSS/RSS/private-dirty/Java/native/graphics memory, descriptor count and rendering-thread count. Instrumentation memory includes the test runner; production-only samples are recorded separately. CPU percentages may exceed 100% because process CPU sums multiple threads/cores. First-art intervals are software-emulator measurements, not hardware latency promises. Periodic screenshots and raw battery/gfx/logcat records are preserved. Full functional, cache/error, location, update and visual suites remain necessary; repeating one loop does not cover every API failure path.

The emulator reports unsupported CPU/GPU power counters and a simulated charging battery. Battery dumps are evidence of this limitation, not valid watts, mAh consumption or real-device battery life. Frame activity, CPU and background-quiescence checks are measurable resource/power proxies only.

The three-cycle pilot passed before the full run, with zero rendering threads after all three closes. A six-cycle Fine/background/recreation pilot and the corrected loading-label audit also passed. A later working-tree rendering-budget pilot passed 19 native tests, including six more cycles; its slow Fine/motion/recreation case fell from 172.580 s in the earlier pilot to 75.1 s, still visibly slow on software GLES and not a controlled hardware benchmark. The final rendering scheduler additionally coalesces callbacks arriving during a slow frame, suppresses recurring artwork draws during touches/settles, pauses covered artwork in settings, and avoids unchanged caption/layout work. The 45-second authored loop, resolution, resting geometry and motion preference are retained. At that checkpoint these scheduling changes still required exact-source revalidation. The completed source-bound outcome and exact APK identity are recorded below. No public feedback, production deployment or stable Release is authorized by this test request.
